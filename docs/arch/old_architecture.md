# Hayaku 项目架构

本文档描述 Hayaku 2.8.2 的代码组织、核心组件、主要运行流程，以及各层之间的依赖关系。

## 1. 总体架构

Hayaku 采用“Python 门面 + pybind11 绑定 + C++ 核心引擎 + 可插拔数据驱动”的分层架构。

```text
│  │ interactive.py │ │ Python API     │ │ analysis / draw             │  │
```

## 2. 代码目录

| 目录 | 职责 |
| --- | --- |
| `hayaku_cpp/hayaku/` | C++ 核心领域模型、指标引擎、回测系统、组合管理和数据驱动 |
| `hayaku_pywrap/` | 使用 pybind11 将 C++ 对象和函数暴露给 Python |
| `hayaku/` | Python API、数据导入、绘图、GUI、交互式研究工具和 Python 扩展组件 |
| `hayaku_cpp/unit_test/` | 基于 doctest 的 C++ 单元测试 |
| `hayaku/test/` | Python 单元测试 |
| `test_data/` | 单元测试使用的 SQLite、HDF5 等测试数据 |
| `docs/` | 中英文使用文档和架构文档 |

三个运行时主目录之间的关系如下：

```text
┌────────────────────┐
│ 用户 Python 策略   │
└─────────┬──────────┘
          ▼
┌────────────────────────────┐
│ hayaku/                    │
│ Python API 与研究工具      │
└─────────────┬──────────────┘
              ▼
┌────────────────────────────┐       ┌────────────────────────────┐
│ hayaku/cpp/core310.so      │◀──────│ hayaku_pywrap/             │
│ Python 动态扩展            │ 编译  │ pybind11 绑定源码          │
└─────────────┬──────────────┘ 生成  └────────────────────────────┘
              ▼
┌────────────────────────────┐
│ hayaku_cpp/hayaku/         │
│ C++ 核心引擎               │
└─────────────┬──────────────┘
              ▼
┌──────────────────────────────────────────────┐
│ SQLite / HDF5 / MySQL / TDX / ClickHouse    │
└──────────────────────────────────────────────┘
```

Python 是面向用户的门面，核心行情对象、指标运算和回测逻辑主要在 C++ 中完成。

## 3. 数据层

`StockManager` 是证券、市场、板块和行情数据的统一入口，采用单例模式。它负责：

- 初始化市场和证券基础信息；
- 管理 `Stock` 对象；
- 根据 `KQuery` 返回 `KData`；
- 预加载常用周期行情；
- 创建和缓存不同类型的数据驱动；
- 管理共享内存及 IPC 数据访问。

```text
┌────────────────┐
│ Python/C++ API │
└───────┬────────┘
        ▼
┌────────────────┐       ┌────────────────────┐
│ StockManager   │──────▶│ DataDriverFactory  │
└───────┬────────┘       └─────────┬──────────┘
        │                          │
        ▼                 ┌────────┼───────────┐
┌────────────────┐        ▼        ▼           ▼
│ Stock          │   BaseInfo   BlockDriver  KDataDriver
└───────┬────────┘   Driver         │           │
        ▼                └─────┬────┘           │
┌────────────────┐             ▼                ▼
│ KData / KQuery │       SQLite / MySQL   HDF5 / MySQL
└────────────────┘                          TDX / ClickHouse
```

主要入口：

- `hayaku_cpp/hayaku/StockManager.h`
- `hayaku_cpp/hayaku/Stock.h`
- `hayaku_cpp/hayaku/KData.h`
- `hayaku_cpp/hayaku/KQuery.h`
- `hayaku_cpp/hayaku/data_driver/DataDriverFactory.h`

## 4. 指标引擎

指标系统使用 Handle/Implementation 结构：

- `Indicator` 是用户持有和组合的轻量对象；
- `IndicatorImp` 保存指标实现、参数、上下文、结果和依赖关系；
- 指标之间可以组成表达式图；
- 计算结果支持缓存、丢弃期和增量更新；
- 内置指标和 TA-Lib 指标统一通过 `Indicator` 对外暴露。

```text
┌────────────────────────┐
│ 指标表达式             │
│ MA(CLOSE, 20)          │
└───────────┬────────────┘
            ▼
┌────────────────────────┐
│ Indicator              │
│ 用户持有的轻量对象     │
└───────────┬────────────┘
            ▼
┌────────────────────────┐
│ IndicatorImp           │
│ 参数、依赖和计算实现   │
└─────┬────────┬─────────┘
      │        │
      ▼        ▼
 KData 上下文  子指标 / 表达式依赖
      │        │
      └────┬───┘
           ▼
┌────────────────────────┐
│ 计算结果与缓存         │
└────────────────────────┘
```

主要入口：

- `hayaku_cpp/hayaku/indicator/Indicator.h`
- `hayaku_cpp/hayaku/indicator/IndicatorImp.h`
- `hayaku_cpp/hayaku/indicator/`
- `hayaku_cpp/hayaku/indicator_talib/`

## 5. 单策略交易系统

`System` 不是单一策略类，而是多个可替换组件的组合容器：

| 缩写 | 组件 | 职责 |
| --- | --- | --- |
| EV | Environment | 判断市场环境是否允许交易 |
| CN | Condition | 判断当前策略条件是否有效 |
| SG | Signal | 产生买入和卖出信号 |
| MM | MoneyManager | 根据资金和风险计算交易数量 |
| ST | Stoploss | 计算止损价格或触发止损 |
| PG | ProfitGoal | 设置或判断盈利目标 |
| TP | TakeProfit | 实现移动止盈等退出逻辑 |
| SP | Slippage | 模拟委托价与成交价偏差 |
| TM | TradeManager | 维护现金、持仓和交易记录 |

单根 K 线的主要处理过程：

```text
┌──────────────┐
│ 读取一根K线  │
└──────┬───────┘
       ▼
┌──────────────┐    ┌──────────────┐    ┌──────────────┐
│ 处理延迟订单 │───▶│ 检查 EV / CN │───▶│ 检查 SG     │
└──────────────┘    └──────────────┘    └──────┬───────┘
                                               ▼
                                      ┌────────────────┐
                                      │ 产生交易信号？ │
                                      └───────┬────────┘
                                         是  │  否
                              ┌───────────────┘  └───────────────┐
                              ▼                                  ▼
                    ┌────────────────┐                ┌──────────────────┐
                    │ MM 计算数量    │◀───────────────│ ST / PG / TP     │
                    └───────┬────────┘                │ 检查退出条件     │
                            ▼                         └──────────────────┘
                    ┌────────────────┐
                    │ SP 计算成交价  │
                    └───────┬────────┘
                            ▼
                    ┌────────────────┐
                    │ TM 更新账户    │
                    └───────┬────────┘
                            ▼
                    ┌────────────────┐
                    │ 下一根 K 线    │
                    └────────────────┘
```

处理过程中存在提前返回和短路逻辑：某个组件触发交易后，当根 K 线可能不再执行后续判断。因此，组件调用顺序会影响交易原因归属和最终回测结果。

主要入口：

- `hayaku_cpp/hayaku/trade_sys/system/System.h`
- `hayaku_cpp/hayaku/trade_sys/system/System.cpp`
- `hayaku_cpp/hayaku/trade_manage/TradeManager.h`
- `hayaku_cpp/hayaku/trade_sys/`

## 7. 策略运行与实盘扩展

`Strategy` 提供事件循环、定时任务和行情处理能力。实盘交易通过 `OrderBroker` 抽象接入外部券商。

```text
┌────────────────┐    ┌────────────────┐    ┌────────────────┐
│ 行情/定时事件  │───▶│ Strategy       │───▶│ System         │
└────────────────┘    └────────────────┘    └───────┬────────┘
                                                    ▼
                                           ┌────────────────┐
                                           │ TradeManager   │
                                           └───────┬────────┘
                                                   ▼
                                           ┌────────────────┐
                                           │ OrderBroker    │
                                           └───────┬────────┘
                                                   │ 用户实现适配器
                                                   ▼
                                           ┌────────────────┐
                                           │ 券商交易 API   │
                                           └────────────────┘
```

仓库提供的是实盘扩展接口，不包含完整的券商订单生命周期、成交回报对账和生产级风控系统。这些能力需要在具体接入层补充。

## 8. 构建与部署

项目使用 Xmake 管理编译、第三方依赖和测试目标。

```text
┌────────────────┐
│ xmake.lua      │
└───────┬────────┘
        ▼
┌────────────────┐       ┌──────────────────────────────────────┐
│ Xmake          │──────▶│ Boost / HDF5 / MySQL / SQLite       │
└───────┬────────┘       │ TA-Lib / pybind11 / 其他依赖        │
        │                └──────────────────────────────────────┘
        ▼
┌────────────────┐
│ libhayaku.dylib│

        ├──────────────▶ core310.so
```

本地统一操作入口为项目根目录的 `op.sh`：

```bash

./op.sh small-test
./op.sh unit-test
./op.sh python-test
```


## 9. 架构特点

### 优点

- C++ 承担大规模指标计算和回测，Python 保持研究接口的灵活性；
- 交易系统组件可独立替换和组合；
- 数据驱动与领域模型解耦，可接入多种存储；
- 同时覆盖单策略、组合、多因子和实盘扩展场景；
- C++ 与 Python 均有测试体系。

### 需要注意的约束

- `StockManager`、全局行情快捷变量等引入了较强的全局状态；
- 导入 `hayaku.interactive` 会触发数据初始化，存在明显副作用；
- 新增公共功能通常需要同步修改 C++、pybind11、Python 类型声明、测试和文档；
- shared 构建依赖多个动态库，独立运行测试二进制时需要正确设置 RPATH 或 `DYLD_LIBRARY_PATH`；
- 回测基于 K 线事件模型，不等同于完整的订单簿和交易所撮合模拟。

## 10. 架构总结

```text
Python 研究与应用层
        ↓
pybind11 语言绑定层
        ↓
C++ 行情、指标、回测与组合引擎
        ↓
数据驱动、数据库、文件和外部交易接口
```

Hayaku 的核心定位是面向中国证券市场的高性能量化研究和回测框架。其优势在于完整的领域模型、可组合的交易系统以及 C++/Python 双层接口；如果用于生产级实盘交易，还需要在券商接入、订单状态机、成交对账、风控和监控层继续扩展。
